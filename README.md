# Physics of Agents - Summary

Experimental repository inspired from [1]. The paper deals with opinion dynamics of agents, using a statistical physics framework to study and predict the results.

In this repository, we try to add/fix some features to obtain a better setup and evaluation.

## 1. Problem setting and purpose of the paper

The paper studies **how opinions of interacting agents change over time**.

The basic idea is:

* We have a group of **agents**.
* Each agent has a **persona**, which describes who they are and provides their initial context for answering a question.
* The agents are asked a **question/statement** and have an opinion about it.
* Agents can **communicate with each other** by sending messages.
* After receiving messages from other agents, an agent can **change its opinion**.
* This process is repeated for several rounds.

The important point is that the paper tries to connect this LLM-based social interaction to ideas from **statistical physics**, such as spins, interactions, and trajectories.

In the code, the LLM acts as the agent's decision-making mechanism. It receives the relevant context — persona, question, and messages from other agents — and produces the agent's current opinion.

The paper then studies the resulting opinion dynamics using a physics-inspired framework.

## 2. Notation and terminology

### Agents

Suppose we have three agents $A_1, A_2, A_3$. Each agent has a fixed **persona**.

For example:
* Agent 1: environmental activist
* Agent 2: economist
* Agent 3: business owner

The persona is part of the agent's background. **It is not the same thing as the agent's current opinion.**

### Spins

The agent's current opinion is represented by a **spin**:

$$
s_i(t) \in \{-1,+1\}
$$

where:

* \(+1\) might mean **AGREE**
* \(-1\) might mean **DISAGREE**

The exact meaning depends on the experiment. For an objective question, the two values can instead represent **A/B**.

For example, at time $t=0$:

$s_1(0)=+1$

means Agent 1 agrees.

If Agent 1 receives messages and changes its opinion:

$s_1(0)=+1$ could become $s_1(1)=-1$

So the **spin changes over time**.

### Interaction matrix \(J\)

The matrix $J$ describes **how agents are connected/interact**. An element $J_{ij}$ describes the relationship from agent \(i\) to agent \(j\).

In the setup we examined:

* $J_{ij}=+1$: attractive/agree-type interaction
* $J_{ij}=-1$: repulsive/disagree-type interaction
* $J_{ij}=0$: no interaction

For example:

$$
J =
\begin{pmatrix}
0 & +1 & -1\\
+1 & 0 & +1\\
-1 & +1 & 0
\end{pmatrix}
$$

means, for example:

* Agent 1 and Agent 2 have a positive interaction.
* Agent 1 and Agent 3 have a negative interaction.
* Agent 2 and Agent 3 have a positive interaction.

### Very important distinction

**$J_{ij}$ does NOT tell us whether the two agents currently agree.**

For example, we could have $J_{12}=+1$ but:

$$
s_1=+1,\qquad s_2=-1.
$$

So the agents currently disagree, even though their relationship is attractive.

Similarly, $J_{12}=-1$ doesn't mean they cannot agree. It means the interaction is treated as repulsive/disagree-type.

### Is \(J\) changed when opinions change?

In the experiment/code we examined, **no**.

The interaction matrix \(J\) is generated when the experimental setup is created and then stays fixed during the forward dynamics.

The opinions/spins change:

$$
s_i(0) \rightarrow s_i(1) \rightarrow s_i(2) \rightarrow \cdots
$$

but \(J\) remains fixed.

This is useful because it allows the researchers to study how opinions evolve under a controlled interaction structure.

### Messages

Agents communicate through messages.

We can denote a message from agent \(i\) to agent \(j\) at time \(t\) as something like:

$$
m_{ij}(t).
$$

The actual message is natural language generated by the LLM.

The message is then placed into the receiving agent's appropriate inbox according to \(J\).

So there is a connection between $J_{ij}$ and how the message from $i$ is treated by $j$.

### Trajectory

A **trajectory** is the evolution of the system through time.

For example, suppose we have three agents.

At time 0:

$$
\mathbf{s}(0)=(+1,-1,+1)
$$

After one interaction round:

$$
\mathbf{s}(1)=(+1,+1,+1)
$$

After another round:

$$
\mathbf{s}(2)=(-1,+1,+1)
$$

The sequence

$$
\mathbf{s}(0)
\rightarrow
\mathbf{s}(1)
\rightarrow
\mathbf{s}(2)
\rightarrow \cdots
$$

is the **opinion trajectory**.

It tells us how the system's state changes over time.

### Replica

A **replica** is one realization/run of the experiment.

For example, imagine we run the same question with the same general experimental setup several times:

* Replica 1
* Replica 2
* Replica 3

Because the LLM can produce different responses, the resulting messages and opinions can differ between runs.

Each replica therefore gives us one possible trajectory:

$$
\text{Replica 1}
\rightarrow
\mathbf{s}^{(1)}(0),\mathbf{s}^{(1)}(1),...
$$

$$
\text{Replica 2}
\rightarrow
\mathbf{s}^{(2)}(0),\mathbf{s}^{(2)}(1),...
$$

This lets researchers study not just **one** outcome, but the behavior of the system across multiple realizations.

## 3. Directory structure

The repository is organized into four main components: the core implementation, data storage, experimental implementations, and results analysis.

```text
.
├── lib/
│   ├── datagen/
│   ├── clean_data.ipynb
│   └── features.py
│
├── data/
│   └── models/
│
├── personal/
│   ├── langgraph/
│   └── mesa/
│
└── analysis/
    ├── opinions_evolution.ipynb
    ├── couplings.json
    └── utils.py
```

### a. Core implementation — `lib/`

Contains the main implementation of the Physics of Agents framework.

- **`datagen/`**: Contains the Python code responsible for generating experimental replicas and running the agent dynamics. This includes agent initialization, interaction networks, opinion sampling, message exchange, and the evolution of opinions over multiple rounds.

- **`clean_data.ipynb`**: Notebook used in the data-processing stage. It loads the raw JSON simulation runs, converts them into a structured Pandas DataFrame, enriches each run with labels from the objective and subjective datasets, and exports a cleaned dataset. 

- **`features.py`**: Contains feature-related code used by the implementation.

### b. Experimental data — `data/`

Stores the data generated and used throughout the experiments.

- **`models/`**: Stores the experimental results in JSON format. Each run contains information about the simulated system, including agents, their personas, messages exchanged, opinions (spins), and their evolution over time.

Other directories contain datasets and intermediate data used by the experiments.

### c. Experimental implementations — `personal/`

Contains experimental implementations and alternative approaches developed to reproduce, explore, and extend the main framework.

- **`langgraph/`**: An initial, simplified implementation using LangGraph. This approach was abandoned in favor of other orchestration solutions.

- **`mesa/`**: An experimental implementation using Mesa, an agent-based modeling framework [2]. It serves as a starting point for exploring alternative orchestration mechanisms and developing new features.

These implementations are experimental and are separate from the main data-generation pipeline.

### d. Results and analysis — `analysis/`

Contains the notebooks and supporting code used to investigate and visualize the experimental results.

- **`opinions_evolution.ipynb`**: Jupyter notebook for analyzing the evolution of agents' opinions over time and exploring the resulting system dynamics.

- **`couplings.json`**: Stores the fitted coupling parameters used in the physics-inspired model.

- **`utils.py`**: Utility functions supporting the analysis notebooks.

### Python environments and dependencies

The project uses different Python environments depending on the implementation.

| Environment | Python version | Requirements |
|---|---|---|
| Main implementation | 3.9.13 | `requirements.txt` |
| Mesa experiments | 3.11+ | `mesa_requirements.txt` |

The Mesa implementation requires a newer Python version and should therefore be installed in a separate environment.

## 4. Running the experiment

| Physics / paper concept          | Where in repository                                      | What it does                                             |
| -------------------------------- | -------------------------------------------------------- | -------------------------------------------------------- |
| **Agent / persona**              | `lib/datagen/collect_energy.py` + `dynamics.py`          | Loads personas and associates persona `i` with agent `i` |
| **Question / statement**         | `lib/datagen/collect_energy.py`                                      | Loads the question given to every agent                  |
| **Interaction matrix \(J\)**     | `lib/datagen/graph.py`                                   | Generates the signed social network                      |
| **Spin / opinion \(s_i(t)\)**    | `lib/datagen/samplers.py` + `dynamics.py`                | LLM produces an opinion; code converts it to ±1          |
| **Messages**                     | `lib/datagen/samplers.py` + `dynamics.py`                | LLM generates natural-language messages                  |
| **Interaction effect of \(J\)**  | `dynamics.py::_build_inboxes()`                          | Places messages into "agree" or "disagree" inboxes       |
| **Forward dynamics**             | `lib/datagen/dynamics.py`                                | Executes message → inbox → opinion updates               |
| **Trajectory collection**        | `collect_energy.py` → `run_forward_dynamics()`           | Runs the dynamics and saves trajectories                 |
| **Replica**                      | `dynamics.py::Replica`                                   | One realization of a question + graph + repeated run     |
| **Trajectory analysis**          | `analysis/*.ipynb`,  | Studies what happened                                    |



**Instructions for data generation**: use the files under lib/. The following command will use the first question (``--limit 1``) from the training and test sets for the subjective dataset (`mode --subjective`). It uses the first four personas (``--num-agents 4``) from `data/subj/personas.json`, one shared graph, two update rounds, and three opinion samples per
agent. `--num-edges 6` specifies six nonzero entries in the symmetric interaction matrix, corresponding to three undirected connections. This demo uses simulated responses through the --mock option, requires no API key, and takes approximately one second on the tested machine. To generate responses using other models, remove --mock and set the OPENROUTER_API_KEY (or others) environment variable. Runtime for API-backed generation depends on response times and rate limits. Run the following command from the repository root.

```bash
python -m lib.datagen.collect_energy \
  --mock \
  --mode subjective \
  --limit 1 \
  --num-agents 4 \
  --num-edges 6 \
  --num-train-graphs 1 \
  --num-seen-graphs 1 \
  --num-fresh-graphs 0 \
  --no-lattices \
  --trajectories 1 \
  --num-steps 2 \
  --k 3 \
  --max-workers 1 \
  --seed 0 \
  --output-dir demo_output
```

The script will write files into the "demo_output" directory. To be able to see the results, move the files into "data/models/mock/subjective_energy", and then run the "clean_data.ipynb" notebook.

From there, it is possible to run the notebooks to study the evolution of the agents' opinion over time and other interesting statistics.
